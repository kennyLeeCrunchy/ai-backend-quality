# 模型接入与输出校验

## 调用契约和预算

- 先沿用项目已有的供应商适配层。明确功能真正需要的能力，例如流式、上下文、工具调用、结构化输出或多模态。选择路由与备用模型时验证这组能力和数据使用约束。
- 为每个用户请求分配总时限、允许的模型调用次数和可执行的资源上限。分别限制排队、首段响应、流中闲置和总执行时间。可强制停止的本地预算由服务端执行，供应商最终计费按其实际回执记录。
- 把错误区分为身份或请求无效、限流、暂时不可用、上下文超限、内容拒绝、响应被截断和输出校验失败。仅在条件允许且仍有预算时重试或切换。供应商已流出内容时，若需要新尝试，使用清晰的尝试和结果语义，避免把不同生成静默拼成一条。
- 保留可诊断的路由结果，包括实际使用的模型与配置版本、尝试次数、首段延迟、失败类型和用量来源。记录经过必要的敏感数据过滤。

## 结构化输出

| 层 | 能执行的保证 |
|---|---|
| 提示词、模型判断 | 引导任务和输出，属于软约束。 |
| 供应商结构化模式与服务端 Schema 校验 | 按实际支持和校验的规则约束格式、字段、类型和范围。记录拒绝、截断及验证失败的明确结果。 |
| 业务验证、事务、权限和工具执行检查 | 判定引用记录是否存在、对象是否归属当前用户、操作是否可执行，并保证实际执行的不变量。 |

模型输出作为业务输入时，先解析、验证和授权，再产生副作用。恢复或修正输出时保留预算和可观察的失败类型。对需要事实正确的输出使用实际数据、确定性校验或有代表性的模型评估；Schema 合法只说明结构通过。

**验收证据**包括模拟超时、限流、无效 Schema、语义错误、流中断和备用模型不具备所需能力。记录重试上限、实际使用模型、局部输出状态和副作用次数。需要真实模型评估时，沿用项目既有的授权和评估入口。
