# API 状态与访问权限

## 状态和错误契约

- 沿用项目明确的状态码、响应结构与版本机制。返回值要能区分验证失败、认证失效、资源拒绝、版本冲突、限流、暂时不可用和结果未知。响应提供客户能安全使用的错误类别、下一步动作和关联请求 ID。
- 对写入返回已提交的新状态或版本。需要后台完成时返回稳定操作 ID，并提供结果查询路径。响应丢失后使用同一操作标识查询或幂等重放。
- 区分工作区资源版本、客户端草稿修订和事件序号。服务端用权威版本仲裁写冲突，响应保留实体 ID 和版本供调用方丢弃已经过时的结果。

## 并发保存

会发生覆盖的更新携带读取时的版本，例如 `If-Match: "v7"`。在同一条件写入或事务里比较版本并更新，包含实体归属。前置条件失败时返回项目约定的冲突语义，使用 `If-Match` 时通常返回 `412` 并让客户端重新获得获准访问的最新版本。重复提交是否返回先前成功取决于能否可靠确认是同一次操作，版本校验与幂等各保留自己的约定。[RFC 9110 · If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)

**例子。** 两个窗口都读取版本 `v7`。窗口 A 保存后变为 `v8`，B 的条件更新命中零行并收到冲突。B 的草稿可保留，服务端返回或提供获准重新读取 `v8` 的路径。

## 身份、权限和持续连接

- 区分身份没有通过认证和当前身份没有资源权限。按现有协议选择 `401`、`403` 或隐藏资源存在性的 `404` 响应，避免在错误和日志中披露越权内容。认证刷新成功后，按当前身份、资源和原操作语义重新授权。
- 项目可用角色、归属或资源授权表表达对象权限，以可信身份和目标资源共同限制读取、修改、流订阅、下载和取消。网关校验的身份上下文经可信链路传入，业务执行点校验资源权限。
- 约定权限撤销对已有订阅、缓存、临时下载链接和排队任务的生效时限。若承诺及时撤销，在推送、Worker 开始或实际副作用前做符合时限的重新校验，并测试旧上下文不能继续使用。对任务是否继续执行及结果可见范围分别定义策略。
- 任务代表用户执行或受服务账号委托时，保存可核验的来源、授权范围和过期条件。账号或租户切换后，状态重用和恢复必须与原资源归属及现有权限一致。

**验收证据**包括两个有效用户同时编辑时只允许约定的更新结果，已生效写入丢失响应后可以查回，重新登录后权限仍被检查，撤销时按承诺停止读取或执行，并覆盖任务、附件和流连接入口。
