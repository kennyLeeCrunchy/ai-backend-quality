# 任务与流式响应

## 选交互模型

按用户可见的承诺选择交互。足够短且掉线后可放弃的动作，用同步调用或与连接绑定的短流；只要求当前进程运行期间继续的任务可以在进程内管理；需要跨实例查询、进程重启后恢复或可靠完成的任务，由共享的持久化状态和执行机制支持。给执行、订阅和取消分别定义契约。

| 操作 | 返回和状态语义 |
|---|---|
| `POST /api/tasks` | 鉴权后创建任务，返回稳定 `taskId` 与初始状态。提交成功表示任务已被可靠接收。 |
| `GET /api/tasks/{taskId}` | 返回当前状态、已提交的结果快照和对应游标。身份、任务归属和租户范围由服务端校验。 |
| `GET /api/tasks/{taskId}/events` | 续接同一任务的事件，提供单调序号和明确的终态事件。 |
| `POST /api/tasks/{taskId}/cancel` | 记录取消请求或返回已存在的终态。请求已接受和执行已经停止用不同状态表示。 |

## 持久化与竞争

- 提交按调用者或租户、操作范围和幂等键去重，用唯一约束保证并发创建最多一条。为同一次用户提交生成一个键，首次提交超时、页面刷新或重新接入时复用该键；明确发起新任务时生成新键。相同键与相同语义返回原任务，不同输入返回明确冲突。创建任务与可靠分发的一致性见[容错与异步消息](resilience-and-messaging.md)。
- 定义 `queued`、`running`、`cancel_requested`、`succeeded`、`failed`、`cancelled` 及允许迁移。用版本条件或事务阻止竞争写入覆盖已提交终态。规定完成与取消同时发生时谁先提交生效，以及外部副作用已经发生时如何呈现实际结果。
- 执行端以持久化租约、所有权或框架提供的等效机制接管任务。防止旧 Worker 在失去所有权后写回结果。只在能够重放的边界重试，具体状态和外部动作见 [Agent 工作流与工具执行](agent-workflows.md)。
- 在一致的持久化边界写入事件及快照游标。高频 token 可批量检查点，明确断电后最多丢失多少尚未提交的增量。终态结果保存后再标记完成。

## 补播和断线

- 定义服务端接受的游标及其优先级，例如 `Last-Event-ID` 和显式 `after` 同时存在时用哪个。校验游标格式、归属和上界，使用单一游标补播。
- 从最近确认收到的序号继续查询持久化事件。实时通知可作为重新查询的唤醒信号，发送结果仍按持久化序号排序。若采用独立的历史回放与实时订阅，记录切换时的游标上界并补查空档。事件已过保留期时，返回明确的快照恢复路径和下一个游标。重新订阅继续使用原 `taskId`。[WHATWG SSE 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)
- 区分断开一条订阅和显式取消任务。关闭连接后释放订阅资源，保留契约承诺继续运行的任务。配置心跳、缓冲上限和慢订阅者处理，用实际入口验证逐段输出。[服务入口与流量治理](service-entry.md)

| 场景 | 可复现的验收 |
|---|---|
| 双击或请求超时后重发 | 并发提交同一键，两次返回相同任务，存储只创建一条；更换输入而保留键返回冲突。 |
| 中途断线、换实例、游标过期 | 任务按契约继续；在历史补播切到实时订阅时插入新事件，核对无缺口。游标过期时从明确的快照继续，最终内容与状态一致。 |
| 取消和完成竞速 | 可识别的终态只提交一次；旧 Worker 或迟到事件不能覆盖终态。 |
| 越权查询、订阅或取消 | 换租户及用户重放同一任务 ID，三个入口均拒绝并且没有泄露任务内容。 |
| Worker 进程结束 | 从已提交的执行状态恢复；用调用计数和持久化结果确认未重复执行已确认的动作。 |
