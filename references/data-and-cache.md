# 数据库、缓存与会话

## 事务和读写路径

- 从实际数据流确认记录的权威来源、写入的事务边界和读到旧值的业务后果。图书详情可以容忍短暂滞后，扣库存和写借阅记录需要保护对应不变量。
- 关键扣减使用符合数据库语义的原子条件更新、锁或约束，检查受影响的行与事务提交结果。多步写入要明确一起提交的范围以及跨资源失败后的处理方式。
- 连接池按全部应用实例和后台 Worker 算总数。应用扩容后重新检查查询计划、锁等待、数据库连接与写容量，再决定优化查询、扩容或加读副本。
- 读副本适用于可容忍延迟的查询。写后立即读、支付或任务终态等看见新值才正确的路径，应使用能满足该一致性要求的读取办法，例如从主库读取或按版本等待。

## 缓存与失效

记录键空间、TTL、命中后的数据语义和数据库提交后的失效方式。旁路缓存可用于热点、可重建的读路径。提交后删除缓存配合过期兜底属于最终一致方案，遇到失效失败或旧读回填时仍可能出现陈旧数据。对关键结果按业务要求选择版本、读主库或采用其他有验证依据的策略。

| 观察到的故障 | 可尝试的最小改动 |
|---|---|
| 单个热点键过期，大量请求并发回源 | 合并并发回源，或在允许旧数据的路径做后台刷新。多实例下确认去重的作用范围。 |
| 无效键反复打到数据库 | 尽早校验可判定的输入。业务允许时，对不存在结果使用短期负缓存，并考虑创建新数据后的失效。 |
| 大量键同一时刻失效，或者整个缓存不可用 | 分散过期时间，给数据库回源设置并发上限和超时，演练降级路径。 |

## 会话与共享状态

登录凭证、服务端会话和业务对象分别有生命周期。多实例共享需要跨请求存活的会话状态，并明确过期、撤销以及登录切换后的访问范围。使用 Redis 等共享存储时确认它是否承担会话权威状态，核对缓存驱逐、重启和故障时的具体登录行为。多租户的查询条件、缓存键和任务所有权应包含实际隔离范围。

**验收证据**包括两个并发请求无法突破库存或配额，写后读符合约定，缓存故障时回源负载可控，以及同一登录在切换实例后仍符合会话和权限契约。
