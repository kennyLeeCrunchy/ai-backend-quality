# 前后端交互契约导航

当界面交互依赖服务端状态、权限或恢复能力时，沿同一条用户操作核对两端。以项目已有 API 契约、事件结构和数据模型为准。设计新能力时明确用户可等待、取消、重试、继续编辑或恢复的条件。

| 用户场景 | 服务端要给出的事实 | 后端参考 |
|---|---|---|
| 生成中切对话或断线重连 | 任务归属、状态、事件游标、快照、终态和再次订阅的办法 | [任务与流式响应](tasks-and-streaming.md) |
| 取消生成和关闭页面 | 操作是否接受、何时实际停止、任务是否继续、已产生结果是否保留 | [任务与流式响应](tasks-and-streaming.md) |
| 文件已上传，等待解析或入库 | 上传操作 ID、附件 ID、处理状态、错误与允许的重试动作 | [文件、附件与产物](files-and-artifacts.md) |
| 双窗口编辑或保存响应丢失 | 提交的实体版本、权威结果、冲突状态与重新读取路径 | [API 状态与访问权限](api-state-and-access.md) |
| 登录过期、切账号、权限撤销 | 当前身份和资源访问结果、订阅能否继续、原操作是否仍能恢复 | [API 状态与访问权限](api-state-and-access.md) |
| 显示模型回复、预览文件或下载产物 | 内容类型、可访问范围、生成版本、引用及链接有效期 | [文件、附件与产物](files-and-artifacts.md) · [Agent 上下文、记忆与检索](agent-context-and-retrieval.md) |

## 对齐和验收

- 对用户可见的操作约定稳定身份、权威状态和结果获取方式。异步提交成功、业务完成、取消接受和确认停止各有独立含义。重试和重连继续引用原操作。
- 约定可呈现错误及机器可判定的错误类别，在同一调用链保留必要的请求或操作标识。服务端实施授权、版本和数据校验，界面根据接口事实展示操作状态。
- 工具结果、模型内容及用户输入返回给客户端时保留内容类型和来源信息，服务端约束读取与写入权限，渲染端按输出上下文执行转义、净化或隔离。
- 同时改前端行为时，按 `ai-frontend-quality` 的前后端交互契约导航核对对应场景。选一条完整用户路径和至少一个相关失败或竞速场景，从实际入口验证两端语义。[后端验证矩阵](verification-matrix.md)
