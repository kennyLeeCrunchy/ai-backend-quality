# Agent 工作流与工具执行

## 运行与恢复

- 业务需要固定顺序或明确批准时，用代码或工作流状态机控制拓扑和执行条件；需要动态选择时，由模型在当前步骤允许的工具与动作内选择。
- 区分会话、一次运行及一次步骤尝试。为运行保存输入引用、当前状态、可恢复的检查点、已确定结果的操作标识及必要版本。恢复时校验工作流定义、权限与相关输入是否仍适用。
- 给循环和并发分支设服务端上限，例如步骤、时间、调用次数和可执行动作。面向用户区分等待批准、等待外部结果、已完成、已取消和结果未知。
- 写外部系统前生成稳定操作 ID 并保存待执行意图。Worker 在外部成功后、记录成功前崩溃时，按提供方回执、幂等键或对账确认结果。如果提供方既无幂等能力也无可靠查询，把结果保存为未知并转入对账或人工核对，本地执行租约只约束本地执行权。恢复从契约允许的边界继续，关联原执行身份。

## 工具和外部数据

- **调用门由服务端执行。** 模型建议调用后，实际执行前做工具白名单、参数 Schema、资源归属、调用者权限和副作用条件检查。对需要批准的操作绑定用户、工具、目标与关键参数，参数或权限变化后按业务规则重新核对。批准状态的检查不能替代写入的幂等保障。
- **工具按最小权限工作。** 数据检索、写入、发布和高影响操作分别限定资源。取回的网页、文档、检索内容和工具结果作为数据处理；嵌入指令不会改变工具授权。凭证留在服务端所需的执行环境，调试输出和事件流只返回业务需要的数据。
- **恢复时重新核对输入和权限。** 使用检查点记录的资源身份和版本，按项目当前权限校验是否还能读取。检索和长期记忆的归属、撤销与来源见 [Agent 上下文、记忆与检索](agent-context-and-retrieval.md)。

**验收证据**包括未批准、越权与参数变更后的操作都未产生副作用；外部调用已成功但本地未落库时恢复能对账；模型选择了无效工具、反复循环或检索到越权数据时，服务端以明确状态终止或拒绝。
